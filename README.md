**Kinema** *(κίνημα — Greek for "movement", the root that gave us "cinema")* generates video from
text using denoising diffusion. It implements [Video Diffusion Models](https://arxiv.org/abs/2204.03458)
(Ho et al., 2022), which extends diffusion from 2D images to 3D video through a **space-time factored
U-Net** — attention that reasons over space and time separately, so video generation stays tractable
on hardware you actually own.

Everything documented here is verified by tests that run on CPU and GPU, on every commit.

## Why Kinema

Research code earns its keep by proving an idea, not by surviving contact with a second machine.
Kinema keeps the architecture faithful to the paper and rebuilds everything around it into something
you can depend on.

| | Typical research implementation | Kinema |
|---|---|---|
| **Devices** | CUDA assumed, `.cuda()` hard-coded | CPU, CUDA and Apple Silicon (MPS) |
| **Resuming** | Optimizer state silently discarded | Model, EMA, optimizer and scaler all checkpointed |
| **Text encoder** | Archived `torch.hub` path, prompts interactively | Current `transformers`, fully non-interactive |
| **Install weight** | Transformers pulled in whether you need it or not | Optional `[text]` extra |
| **Structure** | One 1,000-line file | Seven focused modules |
| **Verification** | None | 22 tests, CI on Python 3.9 – 3.13 |
| **Warnings** | Accumulate quietly until something breaks | Deprecations fail the build |

## Quickstart

Videos are float tensors shaped `(batch, channels, frames, height, width)` with values in `[0, 1]`.
Kinema normalises internally — you never handle the `[-1, 1]` conversion yourself.

```python
import torch
from kinema import Unet3D, VideoDiffusion

model = Unet3D(
    dim = 64,
    dim_mults = (1, 2, 4, 8)
)

diffusion = VideoDiffusion(
    model,
    image_size = 32,
    num_frames = 5,
    timesteps  = 1000,
    loss_type  = 'l1'
)

videos = torch.rand(1, 3, 5, 32, 32)

loss = diffusion(videos)
loss.backward()

# after a lot of training
sampled = diffusion.sample(batch_size = 4)
sampled.shape  # (4, 3, 5, 32, 32)
```

## Text conditioning

### With your own embeddings

Declare their width with `cond_dim` and pass tensors straight through:

```python
model     = Unet3D(dim = 64, cond_dim = 64, dim_mults = (1, 2, 4, 8))
diffusion = VideoDiffusion(model, image_size = 32, num_frames = 5)

videos = torch.rand(2, 3, 5, 32, 32)
text   = torch.randn(2, 64)

loss = diffusion(videos, cond = text)
loss.backward()

sampled = diffusion.sample(cond = text)
```

### With plain strings

Set `use_bert_text_cond` and hand it captions. Requires the `[text]` extra;
`bert-base-cased` (~420 MB) downloads from the Hugging Face hub on first use and is cached.

```python
model = Unet3D(
    dim = 64,
    use_bert_text_cond = True,      # adopts BERT's width automatically
    dim_mults = (1, 2, 4, 8)
)

diffusion = VideoDiffusion(model, image_size = 32, num_frames = 5)

text = [
    'a whale breaching from afar',
    'young girl blowing out candles on her birthday cake',
    'fireworks with blue and green sparkles'
]

loss = diffusion(torch.rand(3, 3, 5, 32, 32), cond = text)
loss.backward()

sampled = diffusion.sample(cond = text, cond_scale = 2.)
```

### Classifier-free guidance

During training, captions are randomly dropped and replaced by a learned null embedding. At sampling
time, `cond_scale` sets how far to push generation away from the unconditional prediction:

| `cond_scale` | Effect |
|---|---|
| `1.` | No guidance — the raw conditional prediction |
| `2.` | Balanced; a sensible default |
| `5.`+ | Strong adherence to the prompt, at the cost of diversity and saturation |

Aggressive guidance can push samples out of range. `use_dynamic_thres = True` on `VideoDiffusion`
enables the percentile-based thresholding from the Imagen paper, which pulls them back:

```python
diffusion = VideoDiffusion(
    model,
    image_size = 32,
    num_frames = 5,
    use_dynamic_thres = True,
    dynamic_thres_percentile = 0.9
)
```

## Training

`Trainer` handles a folder of GIFs, EMA, gradient accumulation, mixed precision, periodic sampling
and checkpointing. It runs wherever your model lives.

```python
import torch
from kinema import Unet3D, VideoDiffusion, Trainer

model = Unet3D(dim = 64, dim_mults = (1, 2, 4, 8))

diffusion = VideoDiffusion(
    model,
    image_size = 64,
    num_frames = 10,
    timesteps  = 1000,
    loss_type  = 'l1'
).cuda()

trainer = Trainer(
    diffusion,
    './data',                       # folder of .gif files
    train_batch_size = 32,
    train_lr = 1e-4,
    train_num_steps = 700000,
    gradient_accumulate_every = 2,
    ema_decay = 0.995,
    save_and_sample_every = 1000,
    amp = True,
    num_workers = 4,
    max_grad_norm = 1.
)

trainer.train()
```

Samples and weights land in `./results`. Every checkpoint carries model, EMA, **optimizer** and
scaler state, so resuming continues the run rather than restarting the optimizer:

```python
trainer.load(-1)      # newest checkpoint
trainer.load(12)      # results/model-12.pt
trainer.train()       # picks up at the exact step it stopped
```

### Choosing a device

```python
trainer = Trainer(diffusion, './data', device = 'cpu')    # or 'cuda', 'mps'
```

Unset, the trainer follows whatever device the model is already on.

### Logging

Kinema logs through the standard `logging` module rather than printing, so it composes with your
own configuration:

```python
import logging
logging.basicConfig(level = logging.INFO)
```

For structured logging, pass a callback — it receives a dict per step:

```python
trainer.train(log_fn = lambda log: wandb.log(log))
```

### Co-training on images and video

The paper argues that factored space-time attention lets you train on stills and video together by
forcing the network to attend to the present moment. `prob_focus_present` arrests attention across
time for a fraction of each batch:

```python
loss = diffusion(videos, cond = text, prob_focus_present = 0.5)
```

### Interpolating between videos

Noise two clips to step `t`, mix them, denoise the result — conditioning is respected throughout:

```python
blend = diffusion.interpolate(video_a, video_b, t = 500, lam = 0.5)
blend = diffusion.interpolate(video_a, video_b, cond = text, cond_scale = 2.)
```

## API reference

### `Unet3D`

| Argument | Default | Description |
|---|---|---|
| `dim` | — | Base channel width; everything scales from this |
| `dim_mults` | `(1, 2, 4, 8)` | Channel multiplier per resolution level |
| `cond_dim` | `None` | Width of your conditioning embeddings |
| `use_bert_text_cond` | `False` | Condition on strings via BERT-base |
| `channels` | `3` | Input channels |
| `attn_heads` | `8` | Attention heads |
| `attn_dim_head` | `32` | Channels per head |
| `init_kernel_size` | `7` | Spatial kernel of the stem convolution (odd) |
| `use_sparse_linear_attn` | `True` | Linear spatial attention at each level |

### `VideoDiffusion`

| Argument | Default | Description |
|---|---|---|
| `denoise_fn` | — | The `Unet3D` to train |
| `image_size` | — | Frame height and width |
| `num_frames` | — | Frames per clip |
| `timesteps` | `1000` | Diffusion steps |
| `loss_type` | `'l1'` | `'l1'` or `'l2'` |
| `use_dynamic_thres` | `False` | Percentile thresholding when sampling |
| `dynamic_thres_percentile` | `0.9` | Percentile used when enabled |

**Methods** — `forward(videos, cond=None, prob_focus_present=0.)` returns the training loss ·
`sample(cond=None, cond_scale=1., batch_size=16)` generates video ·
`interpolate(x1, x2, t=None, lam=0.5, cond=None, cond_scale=1.)` blends two clips.

### `Trainer`

Key arguments beyond the training example above: `ema_decay`, `step_start_ema`, `update_ema_every`,
`save_and_sample_every`, `results_folder`, `num_sample_rows`, `max_grad_norm`, `num_workers`,
`device`. Methods: `train(prob_focus_present=0., log_fn=noop)`, `save(milestone)`, `load(milestone)`.

### Package layout

| Module | Responsibility |
|---|---|
| `kinema.unet` | `Unet3D` — the space-time factored denoiser |
| `kinema.diffusion` | `VideoDiffusion` — forward and reverse processes |
| `kinema.modules` | Attention, resnet blocks, norms, positional bias |
| `kinema.trainer` | `Trainer` and EMA |
| `kinema.data` | `Dataset` and GIF read/write |
| `kinema.text` | BERT tokenisation and embedding |
| `kinema.utils` | Shared helpers |

## Benchmarks

Laptop RTX 3050 (6 GB), `dim = 64`, `dim_mults = (1, 2, 4, 8)`, 32×32 across 5 frames — 35.7 M parameters:

| Operation | Cost |
|---|---|
| Training step, batch 4 | **0.93 s** |
| Peak VRAM, batch 4 | **1.5 GB** |
| Sampling, 4 clips × 1000 steps | **~3.5 min** |

Headroom for batch 12–16 on 6 GB. Sampling dominates wall-clock, as it does for any ancestral DDPM
sampler — a fewer-step sampler is the top roadmap item.

## FAQ

**Which `image_size` and `num_frames` should I start with?**
32×32 at 5 frames trains in reasonable time on a single consumer GPU and is enough to tell whether
your data pipeline works. Scale up only once loss is falling.

**`AssertionError: cond must be passed in if cond_dim specified`**
The model was built with `cond_dim` or `use_bert_text_cond`, so every `forward` and `sample` call
needs `cond`. Build a second unconditional model if you want both.

**Training loss barely moves.**
Expected. Diffusion loss is close to flat while sample quality improves steadily — judge progress by
the GIFs in `./results`, not the number.

**Out of memory.**
Lower `train_batch_size` and raise `gradient_accumulate_every` to keep the effective batch. Then
`amp = True`, then a smaller `image_size` or `num_frames`.

**Does it need a GPU?**
No. Everything runs on CPU and MPS — slowly, but correctly, which is enough to validate a pipeline
before renting a GPU.

**Can I use MP4s?**
Not yet; `Dataset` reads GIFs. Convert with `ffmpeg -i clip.mp4 clip.gif`. Native video decoding is
on the roadmap.
